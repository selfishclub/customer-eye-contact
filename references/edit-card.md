# 2단계: 코어 찾기 · 확인 → 편집 카드

코어가 정하는 것은 **무슨 말을 · 누구에게 · 어떤 톤으로 · 무엇은 빼고**다. 화면 모양은 3 · 6단계에서 레퍼런스와 섞는다.

## 먼저 코어를 찾고, 이게 맞는지 묻는다

사람마다 코어가 다르게 생겼다. 같은 양식에서 시작했지만 고친 정도 · 판 · 자리가 다르다. **바로 읽고 쓰지 말고, 찾은 것을 보여 주고 "이게 지금 내 코어 맞아요?"를 먼저 묻는다.**

### 찾는 순서

1. `코어/코어.md` → 없으면 `코어.md`, `코어/코어_ver*.md` 중 날짜가 가장 늦은 것 → 그래도 없으면 저장소 전체에서 이름에 「코어」가 들어간 md.
2. **다른 브랜치도 본다.** `git branch -a`로 브랜치가 여럿이면 각 브랜치의 `코어/` 파일 날짜를 비교한다(과제를 브랜치에서 한 사람이 있다).
3. 같이 있는 파일을 확인한다: `코어_ver1.md`(지난 판), `코어_ver2_제안.md`(**제안만 하고 아직 코어에 안 넣었을 수 있음**), `장면카드_*.md`, `원장말_*.md` 같은 본인 말 기록.

### 코어마다 다른 점 (2026-11 고객의 눈 2차 참가자 저장소에서 본 것)

| 다른 점 | 어떻게 다루나 |
|---|---|
| 판이 다르다: v0 / ver1.1 / ver2 | 맨 위 `# 내 코어 (…)`와 「상태」 줄을 읽어 판과 날짜를 말해 준다 |
| 한 파일에 인터뷰가 두 번 (위가 새것, 아래는 "재료로 남겨 둠") | **위쪽(새) 인터뷰를 쓴다.** 아래는 재료로만 |
| 「본인 확인: 아직」이거나 "나머지 칸은 문서에서 채운 것" | 그 칸은 AI가 채운 것일 수 있다고 말하고, 편집 카드에 쓰기 전에 확인받는다 |
| `코어_ver2_제안.md`만 있고 코어에 반영 안 됨 | "제안 파일도 있어요. 이것도 반영해서 볼까요?"를 선택지로 |
| 「내 계정에서 통한 것」 칸이 있다 (ver2) | **훅 · 톤에 가장 먼저 쓴다.** 실제로 반응이 온 것이다 |
| 진단 사례 · 원장말 기록 같은 칸이 더 있다 | 말투 · 자주 쓰는 말 근거로만 쓴다. 사례 내용을 자막에 옮기지 않는다 |
| 고객이 「보호자」처럼 다르게 불린다 | 그 사람이 쓴 이름 그대로 쓴다 |
| 코어 파일이 아예 없다 (저장소가 없는 분 포함) | 아래 「코어가 없을 때」 |

### 묻는 법 — 멈춤

찾은 것을 다섯 줄로 요약해 보여 준다.

```
찾은 코어: 코어/코어.md (ver2, 2026-11-24 확정 · 본인 확인함)
- 한 줄: "…"
- 고객: …
- 말투: 존댓말 · 자주 쓰는 말 「…」
- 내 계정에서 통한 것: …
같이 있는 것: 코어_ver2_제안.md (아직 반영 안 된 듯), 장면카드 3개
```

> 이게 지금 내 코어가 맞아요?
> 1. 맞아요, 이걸로 (추천)
> 2. 제안 파일(ver2_제안)까지 반영해서 봐 주세요
> 3. 다른 파일 · 브랜치가 진짜예요 (알려 주세요)
> 4. 바뀐 게 있어요 (말로 알려 주세요 — 이번 편집에만 쓰고, 코어 파일은 본인이 원할 때만 고친다)

### 코어가 없을 때

같은 칸을 질문으로 채운다. 한 번에 하나.
1. 이 영상을 꼭 봤으면 하는 사람은 누구예요? (하는 일 · 고민 한 줄)
2. 평소 말투는요? 존댓말 / 반말 / 반존대, 자주 쓰는 말 하나
3. 영상에 절대 넣으면 안 되는 게 있어요? (업종 규칙 · 개인 기준)

답은 이번 편집 카드에만 쓰고, "코어를 만들려면 스타터킷 `코어_인터뷰.md`로 하면 돼요"라고 한 줄 알린다.

## 읽는 파일 (있는 것만)

| 파일 | 가져오는 것 |
|---|---|
| `코어/코어.md` (없으면 `코어/코어_ver*.md` 중 최신) | 한 줄 · 고객(누구 · 오기 전 상태 · 자주 하는 말) · 말투(존댓말/반말 · 자주 쓰는 말 · 쓰지 않는 말) · 어디까지 나올 수 있나 · 업종 규칙 |
| `규칙/규칙.md` | 금지어 · 금지 장면 (항상 우선) |
| `성과/성과기록.md` | 반응이 컸던 글과 그 반응 종류 |
| `코어/장면카드_*.md` | 이 영상과 같은 장면이 있으면 그 장면의 핵심 |
| 이 영상의 대본 | 어느 글 · 장면에서 나온 영상인지 |
| `규칙/편집스타일.md` | 있으면 지난번 선택 (입구 "지난번처럼") |

## 톤 낱말 3개 만드는 법

말투 칸과 반응 좋았던 글에서 뽑는다. 낱말마다 근거를 단다.

| 코어에 이런 게 있으면 | 톤 낱말 예 | 화면으로는 |
|---|---|---|
| 반말 · 짧은 문장 · ㅋㅋ | 가벼움 · 위트 | 굵은 글자, 튕기는 모션, 이모지 |
| 존댓말 · 설명이 차분함 | 다정함 · 담백함 | 흰 상자 자막, 부드러운 페이드, 색 적게 |
| 숫자 · 목록 · 정리 | 똑똑함 · 정리됨 | 번호 칩, 형광펜 강조, 또렷한 팝 |
| 내 경험 · 고백 | 솔직함 · 따뜻함 | 손글씨 느낌, 따뜻한 색, 느린 줌 |

## EDIT_CARD.md — 멈춤: 확인

```
# 편집 카드
- 이 영상: <파일> · 대본 출처 <글 · 장면카드>
- 누구에게: <코어 고객 한 줄> (코어: 고객)
- 보고 나서 해 줬으면: 좋아요 / 댓글 / 리포스트 / 공유 중 하나 — 이유 (성과기록: <글>)
- 톤 낱말: 1) … (근거) 2) … (근거) 3) … (근거)
- 넣으면 안 되는 것: … (규칙.md · 코어 업종 규칙)
- 내 채널 색: <있으면 색 코드, 없으면 "정하지 않음">
- 얼굴: 아바타 / 직접 출연 / 손 · 뒷모습만 (코어: 어디까지 나올 수 있나)
```

그다음 [core-map.md](core-map.md) 표로 **「코어 반영 계획」(`CORE_MAP.md` 계획 칸)**을 만들어 카드 아래 붙인다. "코어로 이 영상에서 이렇게 바꿀게요" — 칸마다 할 일과 시각. 톤 낱말만 적고 끝내지 않는다.

보여 주고 "톤 낱말이나 계획에서 바꿀 것 있으세요?" 한 번만 묻는다. 코어가 없거나 비었으면 같은 칸을 질문으로 채운다(누구에게 → 바라는 반응 → 톤, 한 번에 하나).
